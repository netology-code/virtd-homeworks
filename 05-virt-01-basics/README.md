## Задача 1

## Задача 2

Выберите один из вариантов платформы в зависимости от задачи. Здесь нет однозначно верного ответа так как все зависит от конкретных условий: финансирование, компетенции специалистов, удобство использования, надежность, требования ИБ и законодательства, фазы луны.

Тип платформы:

- физические сервера;
- паравиртуализация;
- виртуализация уровня ОС;

Задачи:

- высоконагруженная база данных MySql, критичная к отказу;

  Оптимальный выбор будет кластер из физических серверов. Базы данных требовательны к задержкам операций ввода-вывода и частоте процессора, а виртуализация добавляет накладные расходы. Отказоустойчивость в данном случае обеспечивается синхронной репликацией например при помощи Galera. Так же БД активно используют кэш, и в случае физического сервера вся память доступна напрямую, минуя накладные расходы гипервизора.
   Если бюджет не позволяет выделить физические сервера под данную задачу, и потеря производительности не так критична, то менее оптимальным, но приемлимым решением будет использование паравиртуализации.
  
- различные web-приложения;

   Оптимально использование виртуализации на уровне ОС, такой как использование докер контейнеров. Такой подход обеспечивает максимальную масштабируемость, плотность размещения приложений и быстроту восстановления сервисов. Также обеспечиваются низкие накладные расходы, так так нет лишних копий ядра ОС.
  
- Windows-системы для использования бухгалтерским отделом;

   Оптимально использование паравиртуализации. Выбор платформы виртуализации зависит от предпочтений заказчика, но все современные гипервизоры нормально поддерживают Windows системы как гостевые. Паравиртуализация дает хорошую изоляцию гостевых систем, что может быть критично при работе с чувствительными бухгалтерскими данными. Так же упрощается процессы резервного копирования, возможность создания снэпшотов при обновлении, в случае использования кластера имеется живая миграция и высокая отказоустойчовость.
  
- системы, выполняющие высокопроизводительные расчёты на GPU.

   Самая оптимальная платформа в данном случае физический сервер. Виртуализация GPU вносит задержки и ограничивает доступ к некоторым функциям, а на физическом сервере доступ к GPU осуществляется напрямую минуя накладные расходы что критично при высокопроизводительных расчетах.

Объясните критерии выбора платформы в каждом случае.

## Задача 3

Выберите подходящую систему управления виртуализацией для предложенного сценария. Опишите ваш выбор.

Сценарии:

1. 100 виртуальных машин на базе Linux и Windows, общие задачи, нет особых требований. Преимущественно Windows based-инфраструктура, требуется реализация программных балансировщиков нагрузки, репликации данных и автоматизированного механизма создания резервных копий.

   Так как преимущественно Windows based-инфраструктура, то оптимально будет использование Microsoft Hyper-V. В данном сценарии получаем нативную интеграцию с Windows Server и Active Directory. Windows Server Datacenter используется для создания гипервизоров, Hyper-V имеет встроенную рекликацию, продукты семейства System Center используются для централизованного управления инфраструктурой, балансировки нагрузки, создания резервных копий. 

2. Требуется наиболее производительное бесплатное open source-решение для виртуализации небольшой (20-30 серверов) инфраструктуры на базе Linux и Windows виртуальных машин.

   По моему мнению однозначный выбор в сторону Proxmox VE. Опенсорсное решение с бесплатной базовой версией, уже умеет полнофункционыльный веб интерфейс управления, встроенную кластеризацию, поддержку резервного копирования (PBS), поддерживает живую миграцию, ZFS и интеграцию с Ceph. Использую это решение как на работе так и дома.

3. Необходимо бесплатное, максимально совместимое и производительное решение для виртуализации Windows-инфраструктуры.

   Максимально совместимое бесплатное решение для windows-инфраструктуры будет Hyper-V Server. Обеспечивает максимальную совместимость с windows системами. Накладные расходы на виртуализацию отностельно малы, так как устанавлевается непосредственно на физический сервер. Само решение бесплатное, но требуется лицензирование гостевых систем. 

4. Необходимо рабочее окружение для тестирования программного продукта на нескольких дистрибутивах Linux.

   В данном сценарии считаю оптимальным установку на ПК разработчика VirtualBox. Легкость установки и настройки.
